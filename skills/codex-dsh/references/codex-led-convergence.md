# Codex 主导收敛，DSH 调试验收

适合成熟能力承接、复杂重构收尾、跨模块合同收束、正式入口贯通或生产调试：关键矛盾需要较强的整体推理和直接编码，继续交给低成本执行者猜设计、局部修补已经拖慢交付。

Codex 在本场景中是核心开发者，不只是审查者或临时救急者。DSH 团队承担有判断力的材料准备、调试、验收和问题定位，不是只执行固定检查。模型、人数、语言和框架按实际任务选择，不绑定某个项目或固定的两位开发者。

连接、派活、进度观察与回传仍用[协作基础](collaboration-basics.md)。本场景不需要第二条指挥链或新的模式配置。

## 责任分配

| 角色 | 主要责任 |
| --- | --- |
| Codex | 把握完整目标与设计，核对关键实现和原件，裁决跨层责任、合同与根因，直接写齐核心生产代码及必要调用方，判断已有能力是否保住、实际问题是否解决。 |
| DSH 项目主控 | 统筹材料、调试、构件、并行验收、问题归并和接续；确保关键任务有人实际执行，主动解除运行与分工依赖，及时暴露需要 Codex 改代码的具体断点。 |
| DSH 执行者／低成本调查者 | 保全真实来源、整理限定范围的差异和调用链，在明确工作区与构件上运行、定位失败、处理授权范围内的小纰漏，交回可复查的事实和反馈。 |

可以提出推荐，但不能把调查推断写成实测或代替验收裁决。明确的导入、类型、参数接缝等小修可由 DSH 在约定写域内完成；涉及领域语义、架构、权限、生命周期或核心算法的变化交 Codex，避免多个执行者各自猜着重写。发现新事实足以推翻设计时立即带原件沟通，不为测试通过擅自放宽规则。

DSH 主控不因 Codex 写代码而停止推进：继续准备独立材料、整合已交付候选、消化已有失败，安排就绪的真实试验。新反馈不能让原任务无人接续；已足够明确的常规问题由主控处理，不把所有排工和判断退回 Codex。

## 从失败到完整代码批次

先区分会改变下一步的具体未知。DSH 给出真实输入与预期行为依据、最早失败处、准确文件／符号或运行身份、已排除解释及仍缺什么；完整日志留原处，不把全部搜索过程和思考搬给 Codex。不为每个小错误建立报告模板或新状态表。

Codex 直接读足以裁决的关键源码和原件，能确定就立即作选择并写代码。已有成熟实现可继承时先确认有效来源和适用边界，再适配必要接缝；不让 DSH 重新发明原算法，也不把核心实现持续外包成多轮解释和催促。

动手前用现有消息划清写域，保留执行者已完成和在途成果。同一生产链涉及定义、合同、实现、调用方和失败收尾时，一批写到相互一致的正式位置，不能只搭入口或修局部让下游继续猜。未要求的兼容、fallback、占位和砍功能不能拿来遮住缺项。

有多位 Codex 时按完整责任或写域并行，由既有项目沟通关系统一交付 DSH。不能各自指挥同一组执行者、覆盖共同文件或轮流更改同一个未定合同。

## 固定候选后调试

完整代码批交接实际文件／提交、接口和调用方变化、尚未验证的边界与完成含义。候选包含本批必要的新文件，版本身份可由提交或明确快照证明；不要把“代码已写”称为“链路已通过”。

DSH 采用同一候选后集中做受影响编译，修明确的小纰漏，再安排能区分风险的少量核心试验和实际流程。需要并行隔离时，各组使用独立 worktree、数据、端口和匹配构件；复用仍有效的构件，不为每个 case 重新打包，也不把共同树继续变化后的结果归给旧候选。

Codex 与 DSH 不重复跑同一套全量 check/tests。用户指定由 DSH 验证时，Codex 交源码和必要说明，不为制造完成感再代跑一遍。检查失败若暴露设计或生产代码问题，给 Codex 准确反馈集中修复后，补验受影响部分；无新未知不重扫全仓。

用于定位的临时探针、fixture 和串联脚本留在任务证据目录。确有现实可发生的缺陷、能够独立证伪且值得长期维护时，再由 Codex 决定加入聚焦测试；不把临时调试配套全部固化进项目，也不用字段映射、措辞快照或绿色计数充当可靠性。

## 用真实材料判断效果

需要业务回放或 Agent 改进时，复用项目已有 Skill、采集、选样、run／collect 和输入审计能力。低成本执行者可以并行整理优质历史任务、同类失败和新样本，保留来源、身份、对象关系、时间、媒体及必要前情；没有保全的事实标缺失，当前补查另标时点。先交可用材料滚动推进，不等全部来源收齐，也不让材料建设抢占当前核心运行。

Agent 历史回复用于外部质量对照；客户与真实人工输入按其身份、时序和作用进入新链路，不为测试状态而编造接管、归还或其它动作，不提前给出后轮事实。若当前入口不能表达原信息，显式暴露并修工程接缝，不裁掉原文或图片来获得通过。

先核实际角色收到的上下文、工具与资料，再判断回复和动作。区分来源不可用、工程漏供、表达或对象关联失真、能力遗漏，以及充分交付后的模型误用。关键工程缺陷未排除时先修工程；已正常链路的独立优化可继续，不把全仓零问题或每次回复完美作为无限施工前提。

技术运行成功、输入完整、领域动作成立和用户效果改善分别说明。沿同一构件、任务或操作确认原失败点确实跨过，补码被正式采用、实际交付已发生；不能用另一个简单案例、历史成功或测试装置自洽代替。

## 接续与切换

DSH 合并同因问题与真实反例，主动交付可采用的阶段结果或关键阻塞；Codex 据此继续编码和关键抽查，不能只等汇报或等用户发现问题。正常状态不逐条互发，具体同步与等待遵守共用规则。

核心合同和正式链路已稳定、剩余工作可由 DSH 自主实施时，把该范围交回[DSH 主导实施](dsh-led-implementation.md)，带上已验证事实和剩余边界。新的复杂链也可直接采用本场景，不必等项目到了所谓后期才允许 Codex 编码。
