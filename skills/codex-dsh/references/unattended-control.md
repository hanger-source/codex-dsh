# 无人值守的周期介入

适用于用户已授权持续工作，并要求离席、睡眠期间或按周期把控的任务。周期说明何时回来判断进展，不重新决定实现责任；沿当前 [DSH 主导实施](dsh-led-implementation.md) 或 [Codex 主导收敛](codex-led-convergence.md) 接续。

## 按场景推进

DSH 主导实施时，DSH 持续负责主要实现与整合，Codex 定期核对方向、关键原件与卡点，必要时直接补码。Codex 主导收敛时，Codex 对关键设计和生产代码持续负责，DSH 在其间准备材料、调试与反馈；不能退回“DSH 继续猜实现，Codex 偶尔来看看”。

模型、推理档位、调查者与并发按用户选择、宿主能力和当前瓶颈配置，不固定型号或人数，不声称完成了未执行的模型切换。只有允许委派时才使用低成本调查者整理限定证据，它不代替关键判断，也不成为常驻中转。

从上轮未完成卡点、原负责人、写域、构件和真实任务句柄接续。程序内筛新增活动与变化，再读影响判断的原件；看到等待就核实所等对象是否仍推进、已交付或有接续者。`running`、消息收件与测试计数不能证明任务在前进。

## 一次介入产生什么变化

选择当前最严重且能帮助的实际断点：错误假设、合同未定、能力承接遗漏、工程供给失真、依赖互等或关键实现缺项。正常长运行或仍有新证据的工作不因时间久就被接管；没有实际问题就承接正常进度，不硬造任务。

证据足以决定时就行动：给出准确的已有能力与适用边界、裁决跨层取舍，或在明确写域内直接写齐核心代码和调用方。不让反复解释、催促、全景复查、非核心清理或框架建设接管主线。

本批完整后按当前场景交接集中编译、核心试验和真实流程。用户要求 DSH 收尾时，Codex 不重复跑检查；已经有效的证据继续采用，不为新周期或换执行者重做。细节操作与同步边界见[协作基础](collaboration-basics.md)。

当次或后续观察回到同一代码批和实际运行，核对是否真正采用、原失败点是否跨过，不能以收件、承诺或提交代替。结果未到时保留准确负责人、句柄、证据与下一观察点；原卡点解除即返回主线，不反复证明相同成功。

Agent 改进采用项目现有真实任务方法，先排除工程遗漏和输入失真，再判断模型与业务效果。不以全项目零问题作为无限延期条件，也不把框架接通、回放 passed 或模型产文当成效果改善。

## 调度与结束

周期由用户授权并使用宿主已有自动化能力设置；复用现有任务，不另建同题调度、第二主控或持久状态。周期不限制单批代码和长任务总时长，上轮仍在施工就接续原责任，不叠加同题实施。关键失败、返工反证或需决策的阻塞走原生异步回传，不必等下次周期。

每次完成本轮帮助和必要观察后结束，不常驻 sleep、反复轮询或用模型等满间隔。等待沿同一原生句柄并遵守宿主上限。达到用户约定目标或明确停止时，沿宿主能力调整或结束调度；一批完成不自动等于整个项目结束。

成本收益来自减少重复阅读、返工和无效等待，按实际推进判断，不保证固定 token 节省比例，不新增用量统计、监控或机械报告。
