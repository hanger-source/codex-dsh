# DSH 主导实施

适合工作范围较大、责任可拆分，需要 DSH 并行展开设计和实现的任务。允许逐批消化未决接缝，不表示接受无依据的实现、长期混乱或反复试错。

本页定义这一场景的主责。连接、派活、观察和回传用[协作基础](collaboration-basics.md)，不把它的通用操作再写成一套实施流程。

## 责任分配

DSH 项目主控持续负责日常方案、源码实现、分工、调用方接齐、跨模块整合、调试验证与整体交付。执行者负责限定但完整的工作范围；派完任务不移交主控的推进责任。

Codex 保持用户目标、方向、关键决策与独立质量判断，直接阅读关键接口、实现和原件。可以让 DSH 介绍实际对象、责任、依赖和输入到结果的链路，再选择尚未成立或有矛盾的地方深入；不用双方先后读完整仓库，也不只听总结和统计。

DSH 在范围内自主取舍，不把每一步设计变成请示。遇到重要架构分歧或证据冲突，说明分析、推荐和影响；Codex 给出关键判断后，由原负责人继续完成实现与整合。

## 主控持续推进

分工先看实际结构、依赖与写域。执行者工作期间，主控继续处理不依赖其结果但服务当前目标的整合：正式入口与装配是否采用新实现、跨模块合同是否一致、遗漏调用方如何接续、下一项必要试验如何准备。无独立工作才异步等待，不为保持活跃制造重扫、重测或新机制。

收到局部成果就判断能否进入真实链路。文件存在、函数探针通过或单包编译成功，不证明入口已采用，更不证明原责任已退出。把直接上下游接完整，不能只转发 passed 后等 Codex 再找遗漏。

耗时实施开始挤占整体判断时，把一段能独立闭合的完整执行责任交给合适执行者，优先复用原负责人。交接现有成果、失败现场、已排除解释和剩余目标；主控保留优先级、整合与交付判断，不把任务不断切成一次搜索或一条命令后又收回。

并发按原生额度和真实独立性安排，不固定人数或为用满名额增加任务。最高优先级工作须有人实际接手；有空闲成员先接续，额度不足时在可恢复边界调整次要工作。共同依赖未定时先解依赖，不能让多组各猜一套合同。

用户或 Codex 的新反馈先判断是补充、纠正还是替换目标。保留不冲突工作的原责任与恢复点，不因最新消息丢掉前项，也不默认增设秘书或第二主控。收到指导就落到实际分工和实现；认为不适用时带准确反例回来，不只修改报告措辞。

## 完成整批实现

沿当前真实入口、业务规则与已有能力完成相关代码和调用方，再集中受影响编译、修合同或装配遗漏，之后做相称的核心行为与真实流程验证。不要边写每个映射边扩测试，也不因提交或换执行者重跑已有有效检查。

主控核对关键结果与完整目标的关系，保留源码、构件、运行及业务完成之间的边界。采用项目既有方法和有效材料，不为追新结构砍掉原有功能，不以去掉注册或忽略调用方冒充迁移完成。

可用阶段成果或卡点解除后按共用规则主动同步，继续下一项已授权工作；普通修复和测试计数合并处理。没有确切待决事项，不等用户或 Codex 再次安排。

## 何时需要 Codex 更深介入

反复修同一问题仍不成立、根因来回变化、核心合同不清、入口检索重复耗时，或关键路径长时间无新证据时，主动给 Codex 具体失败条件、关键源码与原件、已排除解释及当前推荐。它们是重新判断的信号，不是必须等满某个次数或时长才求助。

Codex 发现自己的判断或直接补码能更快解开一个明确阻塞时，可以在已有授权内主动介入，不必等正式求助。先与原负责人划清写域，保留已有成果，补完整必要代码和调用方；再由原负责人承接整合、验证和后续实施。不能以指导已发送或补码已交接替代原卡点实际跨过。

一次局部介入不自动转移全部实施责任。若当前关键工作持续需要 Codex 直接承担跨层设计和核心代码，明确把该范围切到[Codex 主导收敛](codex-led-convergence.md)，不要继续名义上让 DSH 包办、实际上反复等待高智救急。其它独立工作可保持本场景。
