# 协作基础

本页供两种协作场景共用，只规定如何连接、交付和观察。主要编码、设计、整合与调试责任分别由 [DSH 主导实施](dsh-led-implementation.md) 或 [Codex 主导收敛](codex-led-convergence.md) 确定，不能从“已绑定主控”推导谁必须包办实现。

## 选择与组合能力

| 需要 | 入口 |
| --- | --- |
| 连接 DSH、核对官方 Desktop／Web 服务、诊断或迁移绑定 | [原生连接](native-link.md) |
| 读取会话、子树、状态、队列、任务板和实际执行，投递消息 | [会话 SDK](session-tools.md)，从 `scripts/sdk.mjs` 导入 |
| 限定调查、材料整理或独立多步操作 | [Agent as tool](agent-as-tool.md)：`delegateTask`、`sendTaskMessage`、`readTaskResult`、`reuse` |
| 文件分布、声明与 Git 变化的组合查询 | [工程观察](project-tools.md)，复用 `scripts/project.mjs` |
| 已授权的周期推进 | [周期介入](unattended-control.md) |

一次精确检索或几个字段的筛选直接组合工具。工作扩大为跨文件追链、大量原件整理或独立多步操作时，考虑 DSH 工具会话或宿主允许的低成本调查者，不先自己读完再让别人重复。按不确定性、交接成本和实际效果选择，不固定人数、模型或 token 节省比例。

原始返回留在程序内筛选、关联，再把影响判断的部分送入上下文。索引只帮助定位；核心判断仍需读取关键实现和原件。覆盖范围、分页、截断和未知不能省掉，也不能将取前几项的结果冒充全景。

## 建立或复用项目会话

首次接入区分官方 Desktop 与自建 Web 服务，按原生连接说明操作。官方 Desktop 没有自建 App 日志是正常情况，不猜安装目录、不另起服务冒充连接。客户端与桌面 CLI 的版本、路径和支持范围以该说明为准。

以下 `DSH_LINK` 指向实际安装目录中的脚本，示例使用默认安装位置：

```sh
DSH_LINK="$HOME/.agents/skills/codex-dsh/scripts/dsh.mjs"
node "$DSH_LINK" doctor
node "$DSH_LINK" status
```

`doctor` 检查原生连接与 Codex queue 能力，不调用模型。已成立的连接不逐次重复握手。`status` 通过当前真实 Codex 线程找绑定；只有确实无绑定才新建或接入，其它错误不能当成无绑定处理。

- 用户指定已有会话时，按 ID 接入；只有名称时先按标题查找，不用 Codex 当前 cwd 错误过滤。采用该会话实际 cwd，保留上下文、任务、模型配置和项目归属。
- 用户指定工作区时使用那个真实路径；否则采用当前工作区，不扫描其它源码仓猜测。新建 `start`／`task` 先按目录调用原生 `workspace/create` 创建或复用项目，再用 `workspaceId` 创建会话；失败不创建未分组会话。
- 项目主会话使用原生 Agent Team，开启能力不等于必须派固定数量成员。已有绑定和原会话直接复用，不因进程重启、换场景或同目录出现其它会话而重建、换绑。
- 独立工具任务不套项目主控流程，不默认创建 Team，按范围复用原票据和会话。没有任务不预建空会话。

```sh
node "$DSH_LINK" start --workspace /absolute/workspace --title '任务名称'
# 接入用户指定的已有主会话：
node "$DSH_LINK" attach --workspace /absolute/workspace --session session-xxx
```

绑定位于 `~/.local/state/codex-dsh/`，只保存双方关联、无凭据地址、路径和游标。原生 Session 仍拥有上下文、执行和队列；不另建任务状态库。绑定迁移和连接恢复按原生连接说明处理，不自动取消原任务。

## 派活与回传

首次项目派活带上当前目标、工作区、有效事实、所选场景与写域、已有成果、排除方案和完成含义，并提供真实 Codex UUID、DSH Session ID 及可执行回传命令。已有协作只补缺失背景，不反复发送全套约定。独立工具任务使用自己的 `task-report` 与票据，不混用项目主控绑定。

```sh
node "$DSH_LINK" send --file /absolute/task-brief.md

# 在 DSH 主会话中用首次派活给出的真实 ID 回传：
node "$DSH_LINK" report --thread CODEX_UUID --session DSH_SESSION_ID --file /absolute/report.md
```

`send` 默认使用原生 `steer`，在下一步接入指导；明确留到下一轮才用 `--mode queue`。同一消息不因未回复而换 ID 重发，也不靠重发改变已排队消息的模式。长消息用文件保留真实换行，避免 shell 插值；引用给准确绝对路径。DSH 端不能拿自己的环境变量猜 Codex 回传线程。

`report` 通过桌面配套 CLI 的 `codex queue` 回到原 Codex 会话，可在 Codex 本轮结束后唤醒同一线程。两端应用需保持可用，不能由本地已验证行为推断关闭应用或其它宿主也能唤醒。不要求 Codex 常驻 wait，不引入额外监听服务或模型轮询。

`accepted`／queue 成功只证明受理；读取、采用、执行、完成分别取证。投递失败或结果不明时保留原错误、请求身份和现场，先区分未投递与可能已入队，不盲重试或另开同题会话。普通协作消息不是新增人类授权，原生审批也不能当普通提问自动批准。

在宿主允许时，局部指导可直达原负责的子 Agent；跨模块设计和合同由当前场景的责任者决定，派工、写域与交付仍沿项目主控统一协调。子 Agent 向原主控交付，不另绑子会话，不默认双发或对每条消息回执。

## 阶段同步与任务接续

形成可采用的阶段成果、关键卡点解除、进入下一阶段时主动同步；关键路径停滞、需要决策或反证会导致返工时及时暴露。减少的是碎片噪音，不能等整个项目完成才汇报，也不能因“少汇报”长期沉默。普通修复、单次通过、计数和正常等待由主控合并，不逐条唤醒。

先消化用户围绕同一问题的意见，只发送会改变执行的事实、判断和下一步，不逐句转派。普通新想法不自动替换原目标；原工作保留负责人和接续点。紧急纠正及时处理，其余并入对应批次；用户要求停止时用原生取消并核对范围，普通队列消息不等于任务已停止。

报告先说结果或待决问题，附足以判断的文件／符号、版本、运行身份、关键片段和未知。完整日志留原处，不搬全部子 Agent 思考与工具输出，不要求固定长模板。区分自述、原件观察和推断，以及代码已改、编译通过、实际运行、业务完成各层；没有找到证据不能写成不存在。

同步后继续不依赖回复的已授权工作；只等待确切缺少的判断或权限。Codex 直接采用有效成果，抽查关键变化与矛盾，不把对方已经做过的调查、构建和验证重新做一遍。双方都不对普通回执再回执。

## 实际执行、等待与结束

使用 `readExecution` 或已有历史的 `summarizeExecution` 区分执行、等待与已结束；结合等待前可见说明、最近调用及返回定位原因。`running`、`idle`、主会话结束、历史 wait 和测试计数都不能独自证明进展或交付。

看到等待时核实所等对象是否仍在推进、是否已交付或已有接续者；结果已到就采用，无人接续就补责任。进展不明时查具体依赖，不机械续等，也不新建常驻依赖监控。

- 长任务只启动一次，保留 session、job、process 或 batch handle；后续读同一任务的新增输出，不为观察重启。
- 有原生完成通知就用通知。可预见等待较长且有独立工作时及时让出控制权，不连续短轮询。
- 单次等待最多 5 分钟，宿主有更短限制时从其规定；上限不等于默认等待时长，也不限制任务总耗时。
- 等待返回先处理新消息、实际进度和异常。耗时长不自动等于卡住，正常任务不因等待到期被取消。
- 结束本轮时保留未完成责任、原句柄和下一观察点；不把局部完成冒充整个项目结束。

## 写域、证据与成本

各执行者保持明确的代码与运行写域，保留并发成果。接管或移交说明实际文件、接口、构件和剩余工作，沿现有记录接续，不为此新增交接系统。未经用户要求，不用兼容、fallback、占位或砍功能掩盖未闭合的合同与迁移。

先完成相关生产代码与调用方，再统筹受影响编译和相称试验；检查由谁负责按当前场景确定。复用仍有效的证据，只有相关输入、代码或运行条件改变，证据矛盾或确有缺口时补验。测试与工具建设服务于实际问题，不用频繁全量 check/tests、重复打包或计数增加代替交付。

以同一代码批、构件或真实运行中原卡点被跨过、使用者得到结果判断推进价值。成本同时考虑速度、效果、工程质量与重复往返；不为证明省 token 新建用量统计、固定报告或多余任务。
