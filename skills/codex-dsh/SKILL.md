# Codex × DSH

把高智能判断和编码、低成本并行执行用在合适的工作上。用户主要与 Codex 对话，Codex 保持整体目标与质量判断；谁负责主要实现，按当前任务选择，不由连接方式或模型价格决定。

## 选择协作场景

| 当前工作的主要需要 | 使用说明 |
| --- | --- |
| 大范围铺开实现，责任可以拆分，DSH 能自主完成设计、编码与整合 | [DSH 主导实施](references/dsh-led-implementation.md) |
| 收束跨模块合同、承接已有能力、打通正式链路，需要 Codex 直接承担关键生产代码 | [Codex 主导收敛，DSH 调试验收](references/codex-led-convergence.md) |

用户已明确分工时直接采用。未指定时按实际瓶颈选择，不必每次让用户选择模式。两种场景都有价值：前者不表示可以忽略质量，后者也不表示 DSH 只能机械跑命令。

场景可以按工作范围并存，不按项目日期、开发天数或模型名称机械切换。切换时说明哪些责任和写域移交，保留已成立的结果、原执行者与未完成工作；不重建主会话，不增加模式状态或审批流程。

## 共用基础能力

连接、绑定、SDK、观察、派活、异步回传、等待和证据边界统一见[协作基础](references/collaboration-basics.md)。首次使用或需要相应操作时按该页进入具体能力；它不预设 DSH 或 Codex 是主要开发者。

独立检索、材料准备和多步操作可以在两种场景中使用 [DSH Agent as tool](references/agent-as-tool.md)。这是普通 Session 工具能力，不是第三种项目主控模式，也不占项目主控绑定。

只读当前任务需要的文档，不默认把两份场景说明和全部 API 装入上下文。项目协作首次派活或责任改变时，把所选场景的关键分工与具体目标合并告知 DSH；普通后续只传增量。

用户授权无人值守或周期把控时，使用[周期介入](references/unattended-control.md)，沿当前场景和同一任务接续；不自动建立定时任务。

## 共同边界

- Skill 不扩大用户授权，不修改全局模型、权限或并发配置；实际能力和模型未知时不猜测。宿主禁止委派或联系子 Agent 时，不通过 DSH 绕过限制。
- 沿已有项目主控统一分工和整合。多个 Codex 可在明确写域内协作，但不各自向同一 DSH Team 重复派活；不默认增加秘书或固定中转。
- Codex 直接承担目标、关键取舍与质量判断，亲自核对足以支持结论的核心实现和原件，不能只转话、只看报告或等用户发现遗漏。
- 省 token 依靠按责任分工、程序筛选、复用有效证据和减少重复试错；不能靠丢掉关键输入、跳过实际交付或长期失去进度感知。
